# games/ — 决策层接管真实页面（游戏跑在页面里，没有后端）

两个真页面：**贪吃蛇**与**俄罗斯方块**。状态、规则、渲染全在页面自己的 JS 里
（`snake.html` / `tetris.html` + `core/*.js` 纯函数），**没有任何后端进程**，
页面里也没有权威状态的第二份拷贝。决策层（主 Agent 调 `decision_run`，环境选 `browser`）
通过浏览器插件**读页面上的局面文字、点页面上的真按钮**来玩。
页面地址加 `?takeover=1` 就是**接管模式**：人类控件收起，插件看到的可点元素恰好是四个策略按钮。

## 目录

| 文件 | 作用 |
| --- | --- |
| `serve.mjs` | 静态服务器：只发文件，**没有任何 API**（见下） |
| `index.html` | 大厅：两个游戏的入口、难度档一览、localStorage 记录总览 |
| `snake.html` | 贪吃蛇。状态、规则、渲染、接管面、记录，全在这一页 |
| `tetris.html` | 俄罗斯方块。同上 |
| `core/snake-core.js`<br>`core/tetris-core.js` | 游戏规则纯函数：状态、合法动作/落点、推进、事实、4 个策略、`*LayaState` / `*StrategyCriteria`（不依赖 DOM 与后端） |
| `core/records.js`<br>`core/ui.js`<br>`core/zh.js` | localStorage 记录层 / 共用渲染工具 / 中文文案 |
| `style.css`<br>`时序图.md` | 三个页面共用样式 / 一次接管任务的时序、判据与失败模式 |

## 架构：谁持状态

```text
主 Agent ──decision_run(environment: "browser")──▶ 决策层执行器
                                                        │ 观察 / 点击
                                                        ▼
                                            浏览器插件（读页面正文、点编号元素）
                                                        │
                                                        ▼
                        snake.html / tetris.html ← **唯一权威状态在这里**（import core/*.js 纯函数）
```

- **状态只有一份**：页面里的 `let state`。谁想知道局面，就读页面。
- **观察面**：`<pre id="model-state">` —— 那段文字是插件快照正文的一部分，模型读到的就是它。
- **动作面**：`<div id="strategy-buttons">` 里的 4 个按钮，按钮 id 就是候选 id。
- **记录**：localStorage，由页面自己写（见「记录与存档」）。

## 怎么跑起来

```bash
node games/serve.mjs               # 默认 127.0.0.1:8787
node games/serve.mjs --port 9000   # 换端口
```

然后浏览器打开 `http://127.0.0.1:8787/`（大厅）、`/snake.html`、`/tetris.html`。
两个游戏跑在**同一个 origin**（一个端口服务两页），所以 localStorage 是同一份。

`serve.mjs` 的能力边界是刻意做小的：

- 只有这些路径：`/` → `index.html`、`/snake.html`、`/tetris.html`、`/js/*` → `core/`、`/style.css`；
- 响应头 `cache-control: no-store, must-revalidate`（改了源码刷新就是新的 —— 不带这个头会一直看缓存副本，这个坑踩过）；
- **没有任何 API**：`/state`、`/action`、`/render`、`/health` 一律 404，这是刻意的。

## 决策层怎么接管

```jsonc
{
  "environment": "browser",
  "objective": "完整地玩一局贪吃蛇。你每次只做一个决定：选择接下来一段时间里蛇要执行的策略。一直玩到本局结束。",
  "completion": { "path": "main", "includes": "【本局结束】" }
}
```

浏览器任务必须给 `completion`（或适配器实现 `isDone()`），否则执行器直接以 `invalid_request` 拒掉。
objective 里要写清「**你只选策略**」：候选集就是那 4 个按钮，目标若写成「选下一步往哪走」，
模型会去找一个不存在的动作。

接管面只有两样东西：

1. **`<pre id="model-state">`** —— 给人看、也给模型读的局面文字。蛇：棋盘大小、分数、长度、步数、
   朝向、食物相对蛇头（dx/dy/距离）、可达空格、障碍物、离自身尾部、本局动作数、每动作步数、
   一张与画布逐格一致的盘面图（`@` 蛇头、`o` 蛇身、`*` 食物、`#` 障碍、`.` 空，20×20，
   `?board=0` 关掉），末行是 `【进行中】` 或 `【本局结束】{...}`。方块：棋盘、分数/消行/等级/已放、
   当前块与下一块、各列高度、空洞数（这两项**只算已固定块**，不含当前方块 —— 行里显式注明了）、
   一张同口径的堆叠图（`#` 已固定、`G` 垃圾行、`@` 当前方块、`:` 落点预览、`.` 空，画满 20 行，
   图例就是图上那一行）、本局动作数、同样的末行。
2. **4 个策略按钮**，按钮文字来自 core（`snakeStrategyCriteria()` / `tetrisStrategyCriteria()`），
   每帧按当前局面重写：

   | 游戏 | 候选 id |
   | --- | --- |
   | 贪吃蛇 | `strategy:chase` / `strategy:survive` / `strategy:hug` / `strategy:straight` |
   | 俄罗斯方块 | `strategy:lines` / `strategy:holes` / `strategy:flat` / `strategy:low` |

点一次 = 蛇按该策略**连走 8 步**（`?steps=N` 改），方块按该策略**算一个落点放下去**。

**文字图必须与画布逐格一致**：画布上有什么，图上就有什么。方块页画的是「已固定块 + 当前方块 +
半透明落点预览」，文字图就按同一口径拼，而不是只画 `state.board` —— 只画 board 时，当前方块那 4 格
在画布上明明有、在图上凭空消失。蛇页同理（`@` 蛇头、`o` 蛇身、`*` 食物、`#` 障碍、`.` 空）。
两边都**画满 20 行**、不截取底部若干行：截取会让「自第几行起」随局面变化，行对齐又多一层出错机会。

复验方式（可现场重跑）：逐格采样画布（`CELL = 30`，取每格中心像素，与背景 `rgb(11,13,18)` 比色距）
再与文字图对比，逐格差异应为 0；落点预览的色距正好是实心格的 28%，与 `globalAlpha = 0.28` 对得上。
实测两张图都零差异：方块页状态文字 **365 字符 / 27 行**，蛇页 **558 字符 / 27 行**（1 头 2 身 1 食物 8 障碍）。

**图有没有用（A/B 实测）**：同种子各跑「有图 / 无图」两遍，**逐项完全相同** —— 513688 都是
48 分 / 51 长 / 706 步 / 89 动作 / 撞障碍，850752 都是 39 分 / 42 长 / 619 步 / 78 动作 / 撞障碍。
候选描述里已经带了「食物几步远、可达空格多少」，多一张图不动 argmax。**所以图的收益是「页面显示的
就是模型看到的」（可核对、死因一眼可见），不是涨分**；顺带说明同种子 + 同输入 → 整局完全确定性，A/B 无噪声。

**takeover 模式的候选集（实测）**：`?takeover=1` 会收起 `.toolbar` 与页头链接，此时插件快照里的
Interactive elements **恰好是这 4 个按钮**。不带 takeover 时，人类控件与「本地启发式自动走」
按钮也在页面上，它们会一起进入候选集 —— 接管时请用 `?takeover=1`。（一局开始后，页头链接本来也会收起。）

页面参数（以代码为准，`snake.html` / `tetris.html` 开头的 `params.get`）：

| 参数 | 作用 | 现状 |
| --- | --- | --- |
| `?takeover=1` | 收起人类控件，候选集只剩 4 个策略按钮 | 两页都生效 |
| `?steps=N` | 点一次策略连走多少步（默认 8） | 只有蛇页 |
| `?pace=N` | 逐格动画的毫秒数（蛇默认 110） | 只有蛇页真的在用；方块页解析了但页面没有动画 |
| `?difficulty=easy\|normal\|hard\|extreme` | 开局难度（默认 `normal`） | 两页 |
| `?hide=1\|0` | 是否隐藏棋盘（不给就读 localStorage 里的记忆） | 两页 |
| `?board=0` | 关掉蛇页的盘面文字图（默认开） | 只有蛇页；A/B 用 |
| `?seed=N` | 可复现基线：**第一局用 N**，之后每开一局 `N+1`、`N+2`……（不给就每局随机） | 两页；`?seed=513688` 实测页面显示 513688，且能复现同一局 |

## 为什么是这个粒度（实测数字）

三组对照，只改「模型负责到哪一层」，种子与难度固定：

| 粒度 | 模型负责 | 页面代码负责 |
| --- | --- | --- |
| 逐步 | **每一步**选方向 / 选落点 | 忠实执行 |
| 逐步 + veto | 同上 | 会立刻死 / 会自陷的选择被驳回，改走启发式 |
| **策略（采用）** | 每 N 步选一次**策略** | 按策略算出每一步（`snakeStrategyAction` / `tetrisStrategyPlacement`） |

**🐍 贪吃蛇（种子 7，普通）**

| 粒度 | 得分 | 步数 | 长度 | 结局 |
| --- | --- | --- | --- | --- |
| 逐步 | **0** | 16 | 3 | 撞障碍物死亡 |
| 逐步 + veto | **1** | 300 | 4 | 没死，跑满预算 |
| **策略** | **12** | 166 | 15 | 撞墙死亡 |

**🧱 俄罗斯方块（种子 11，普通）**

| 粒度 | 得分 | 消行 | 方块数 | 结局 |
| --- | --- | --- | --- | --- |
| 逐步 | **600** | 5 | 33 | 顶死 |
| 逐步 + veto | **600** | 5 | 36 | 顶死 |
| **策略** | **55400** | **95** | 200 | 没死，跑满预算 |

结论：**这个模型的决策能力体现在「选哪种打法」的粒度上，不在每一步的微操上。**
让模型逐步选，蛇 16 步 0 分就撞死；让它只选策略、确定性代码负责执行到这 8 步的全部细节，
蛇 12 分 / 166 步 / 长度 15，方块 55400 分 / 95 行且没死。页面只暴露 4 个策略按钮，
正是为了让题目落在它真正擅长的粒度上：在有限选项里选一个，剩下的交给确定性代码。

> 注：上面「策略」那一列的数字是经由**已删除的桥**测出来的（种子与规则没变），数字本身可复跑；
> 但当时另有一组对照发现模型倾向锁定列表里的第一个槽位 —— 所以这些分数主要记在
> 「策略粒度 + 本地执行」这个组合上，不能直接当作「模型会挑策略」的证据。

## 页面为了可接管性做的三件小事

1. **按钮节点只创建一次**，之后只改文字和禁用态。浏览器插件按**元素身份**给可点元素编号
   （节点被换掉就得重新编号），每次渲染都重建按钮会让编号抖动；而且按钮文字里带着随局面变化的
   说明（`the food is 15 steps away`、`389 cells reachable`），不每帧刷新的话，模型会照着
   **过期**的描述做选择。
2. **状态立刻结算，动画只是事后播放**。点一次策略，页面先把 8 步的**结果**算完并渲染，
   再逐格播放动画（动画只改画面，不回写局面）。否则「正在执行」的那个窗口会污染接管方
   看到的状态。
3. **禁用规则只有一条：`!alive()`**，执行中**绝不**禁用。一旦在执行窗口里禁用，
   接管方那一刻观察到的候选集就是空的 —— Laya 会直接报 TopK 维度错误（实测过）。

## 记录与存档

**只用 localStorage**，由页面自己写，不经过任何进程。

- 键：`dsh-decision-engine.records.v1`；兼容读取旧键 `laya-router.records.v1`。
- 结构 `{ snake: [...], tetris: [...] }`，**也接受早期版本的扁平数组**（按每条自己的 `game` 分桶）；
  形状认不出来就返回 null，让 `loadAll()` 继续试下一个键。每个游戏上限 300 条；两个游戏同源，记录合并。
- **一次性迁移**：模块加载时把旧键里的记录并进新键，按 `id` 去重，标记位
  `dsh-decision-engine.records.migrated.v1`（清空记录时一并清掉）。桥时代那几局因此能重新看见。
- 一条记录：`{ id, at, game, engine, mode, strategy, score, durationMs, difficulty, detail }`。
  `durationMs` 就是页面上的用时；桥时代的老记录没有这个字段，列表里显示 `-`。
- **`engine` 按「谁在开这一局」写**，依据是事件可信度：插件点策略按钮 = 合成事件
  （`isTrusted === false`）→ `decision-layer`；人点按钮 / 按键 = 可信事件 → `human`；
  本地启发式自动走 → `local`；一局里换过驱动方 → `mixed`（`ENGINE_LABELS` 里有「混合」）。
  以前这里写死 `human`，于是决策层打出来的成绩全被记成「人类」—— 一眼就能看出不对。
- 函数都在 `core/records.js`：`addRecord` / `listRecords` / `recentRecords` / `bestByEngine` /
  `bestByDifficulty` / `summary` / `sessionLesson` / `clearAll` / `exportAll`。
- 为什么记录归页面：游戏就在这里跑，页面开着才记得到；两个游戏同源（一个端口服务两页），记录合并在一起。

## 与插件两种接入方式的关系

| | **浏览器环境接管**（本目录用这条） | HTTP 任务接管（游戏不用） |
| --- | --- | --- |
| 传给 `decision_run` | `environment: "browser"` | `endpoint: "http://…/"` |
| 谁提供状态 | 页面自己（插件读正文） | 环境服务实现 `GET /environment/state` |
| 谁执行动作 | 插件点页面上的元素 | 环境服务实现 `POST /environment/action` |
| 文档 | [任务接管协议](../docs/任务接管协议.md) §1 | [任务接管协议](../docs/任务接管协议.md) §2、[外部接入规范](../docs/外部接入规范.md) |

`endpoint` 这条（`dsh-environment/v1`：`GET /environment/state` + `POST /environment/action`）**仍然存在、
仍然有文档**，只是这两个游戏不再需要它：游戏本来就有真实页面，插件直接读页面、点按钮，
不必再另开一套协议、一套节拍和一套记账。

**被删掉的桥**：原来 `games/bridge/server.mjs` 在第二个进程里复制了一份游戏状态，并对外提供
`dsh-environment/v1` 的 `/state` + `/action`。删掉它的原因是**状态有了两份**：同一个游戏既在
页面里跑、又在桥里演算，两边会漂移；而且决策循环的节奏被前端渲染干扰。现在页面是唯一所有者。

**候选集里不能有 no-op**：从 v0.2.2 起，浏览器适配器在页面已就绪（`status` 不再是 `loading`）时
不再提供 `wait` 候选。原因是模型是确定性的：「什么都不做」一旦被选中，页面不变 → 输入不变 →
每一步都选它，三次就被执行器的 `no_progress` 守卫判死。页面侧不需要为此做任何事 ——
当前行为查 `src/environments/browser/adapter.ts` 的 `#candidatesFor`。

## 已知限制

- **盘面图不涨分**：A/B 实测有图 / 无图逐项完全相同（见上）；它的价值是「页面显示的就是模型看到的」，不是提高成绩。
- **决策水平受 provider 限制**，与页面无关。要提升只能换 provider 或做标定/微调。
- **接管时页面仍然是人可以碰的**：插件点的是页面上那 4 个真按钮，人类点的也是同一批 ——
  同一时刻只让一个驱动方动手，页面不做互斥（真混着来会在同一条记录上留下 `mixed`）。
  本地启发式自动走与人类键盘操作都还在，它们是离线对照用的，不经过决策层。
